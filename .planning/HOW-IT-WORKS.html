How It Works

Infrastructure, tech stack, and what to say when someone asks.

The Stack — What It's Built On
LayerWhatNotes

How It Actually Works — Step by Step
1
Inspector takes photos on site
Compliance plate, build plate, odometer, exterior walkaround, interior, any damage. More photos = better results. On laptop: drag photos straight from Finder onto the upload zone.
2
Photos upload and compress
iPhone 15 photos are ~6MB each. The app compresses them to ~400KB before uploading — preserves quality, massively reduces storage and upload time. Photos stored in Supabase Storage in Sydney.
80-photo limit per asset. Free tier has 800MB headroom remaining.
3
AI reads the plates and extracts every field
Server sends photos to GPT-4o with a detailed prompt specific to that asset type (truck, excavator, forklift etc.). GPT-4o reads the compliance plate, identifies make/model/year/VIN/GVM and 20+ other fields. Returns structured data. Each field gets a confidence score — "from photo" (read directly) or "AI estimate" (inferred from model knowledge).
15–20 seconds. Asset-type-specific prompts: trucks, earthmoving, forklifts, trailers, marine, agriculture, caravans, vehicles, general goods.
4
Inspector reviews every extracted field
Nothing saves until a person confirms it. Inspector sees all extracted fields with confidence badges, can edit any of them. Type plain English into the AI fill box ("no keys, purple, 80,000km") and matching fields fill automatically. Mandatory review step — the AI is a drafter, not a decision-maker.

Before extraction runs: on the photos page, type plain English observations into the 'Tell the AI' box — "no keys, bull bar, high hours, rough interior". These format into inspection notes that feed into the extraction. Stronger notes → better extraction.
5
Auction description generates
GPT-4o writes a professional auction description using the confirmed fields and photos. Asset-type-specific templates: prime movers, tippers, excavators, forklifts, caravans, marine etc. — each formatted to Slattery's style. Inspector can edit before saving.
Standard tone: full multi-line spec description. Quick tone: 2–4 sentence summary.
6
Output: copy, download, or push
Copy All to Clipboard — one button copies all Salesforce fields + description, ready to paste.
Download Excel — generates a .xlsx file with all fields as column headers, values in row 2. For valuers who track in spreadsheets.
Push to Salesforce — with IT's sandbox setup, one button creates the Asset record directly. No clipboard step.
What to Say When Asked
💬 You don't need to know every technical detail. "Good question — let me follow up on that in writing" is always fine for deep IT questions.
"How accurate is it?"
It reads the actual plate, so VIN, GVM, compliance date are reading the exact number printed on the metal. For engine and transmission it infers from make/model/year knowledge — same thing a book-in person would do by looking it up. The review step exists so nothing incorrect gets through.
"For plate data it's reading exact numbers. For specs it makes an educated guess that the inspector confirms. Nothing saves until a person reviews it."
"What happens to the photos?"
Stored in Supabase in Sydney, tied to the user's account. Only that user can access them — database-level access control, not just app logic. Not public. The only external system that sees them is OpenAI for the extraction call.
"Photos stay in Australia. Only the person who uploaded them can access them. OpenAI sees them briefly for extraction, then that's it."
"What if the AI gets something wrong?"
The inspector fixes it before it saves. The review step isn't optional — you can't skip it. In practice, the AI is wrong less often than manual data entry, and when it is wrong it's obvious (misread digit, wrong engine series). The inspector catches it.
"There's a mandatory review step. You can't skip it. If the AI gets something wrong, the inspector fixes it before anything saves to Salesforce."
"What if it misses a detail?"
Before you run extraction, you can tell the AI what you noticed on site — type it in plain English and it formats automatically. After extraction, the review step lets you edit any field. Nothing saves without a person confirming it.
Simple version: "You tell it what you saw, it fills the form. You check it before it saves."
"Can it handle all our asset types?"
Nine categories: trucks (prime mover, tipper, tray, pantech, all subtypes), trailers, earthmoving (excavator, dozer, loader, grader, forklift), agriculture, marine, caravans, vehicles (ute, sedan, SUV), general goods. Each has a specific extraction template and description format.
"Trucks, trailers, earthmoving, ag, forklifts, marine, caravans, utes — all the categories Slattery books daily."
"Who pays for the AI?"
Currently paid personally via an OpenAI account — part of the roughly $900/year running cost. If Slattery wants to take it over formally, they'd set up their own API key. The cost per asset is tiny — roughly 5–10 cents per book-in for the AI calls.
"I'm covering the AI costs as part of the overall running cost. About 5–10 cents per asset. Happy to work out the billing structure if we formalise it."
"What if OpenAI goes down?"
The app still works — you can still browse assets, review and edit fields manually, and copy the output. Only extraction and description generation pause until OpenAI comes back. In practice this is very rare and usually resolves in minutes.
"If OpenAI has an outage, extraction and description generation pause. Everything else works. Fallback is the same manual process as today — no data is lost."
Known Limitations — Be Honest If Asked
Free Supabase tier: 1GB storage limit. Currently using roughly 200MB with 486 photos. Fine for a pilot. National rollout would need a paid plan (~$25/month).
Single server: If the DigitalOcean server has an issue, the app goes down. PM2 handles crashes automatically but a hardware failure would need manual intervention. For a pilot this is acceptable. For national rollout, would want more robust hosting.
AI isn't perfect: Occasionally misreads a digit on a plate or misses a field. The review step catches these. It's faster to fix one wrong field than to type all 34 from scratch — that's the value even when it's not perfect.
Salesforce integration not live yet: This is exactly what Wednesday's ask is about. Currently copy-paste. The IT sandbox setup is the missing piece.
No offline mode: Needs internet to upload photos, run extraction, and generate descriptions. Works on venue Wi-Fi or mobile hotspot.
